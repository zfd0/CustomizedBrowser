# Customized Browser 开发者文档

## 项目概述

Customized Browser 是一个基于 .NET 8 + WPF 开发的多实例隔离浏览器，支持多账户同时登录、数据隔离、后台运行等功能。

### 技术栈

- **框架**：.NET 8.0 (LTS)
- **UI 框架**：WPF + MaterialDesignInXaml
- **浏览器引擎**：Microsoft.Web.WebView2
- **MVVM 框架**：CommunityToolkit.Mvvm
- **依赖注入**：Microsoft.Extensions.DependencyInjection
- **JSON 处理**：System.Text.Json

### 项目特点

1. **多实例隔离** - 每个实例拥有独立的数据目录
2. **MVVM 架构** - 清晰的代码分层
3. **依赖注入** - 松耦合的组件设计
4. **统一术语** - 详见[术语表](./术语表.md)

## 架构设计

### MVVM 模式

项目采用标准的 MVVM (Model-View-ViewModel) 架构模式：

```

│  - SettingsWindow.xaml                  │
└──────────────┬──────────────────────────┘
               │ 数据绑定
               ↓
┌─────────────────────────────────────────┐
│        ViewModel (视图模型层)           │
│  - MainViewModel                         │
│  - InstanceManagerViewModel              │
│  - SettingsViewModel                     │
└──────────────┬──────────────────────────┘
               │ 调用服务
               ↓
┌─────────────────────────────────────────┐
│         Service (服务层)                 │

│  - ISessionService                       │

│  - IWebViewService                       │
└──────────────┬──────────────────────────┘
               │ 数据操作
               ↓
┌─────────────────────────────────────────┐
│         Model (数据模型层)               │
│  - BrowserSettings                       │

└─────────────────────────────────────────┘
```

### 依赖注入

项目使用 Microsoft.Extensions.DependencyInjection 进行依赖注入，所有服务和视图模型都在 `App.xaml.cs` 中注册。

#### 服务注册

```csharp
// 注册服务（单例）
services.AddSingleton<ISettingsService, SettingsService>();
services.AddSingleton<IInstanceService, InstanceService>();
services.AddSingleton<ISessionService, SessionService>();
services.AddSingleton<ITrayIconService, TrayIconService>();
services.AddSingleton<IWebViewService, WebViewService>();
services.AddSingleton<IInstancePackageService, InstancePackageService>();
services.AddSingleton<ISiteDataService, SiteDataService>();
services.AddSingleton<ISiteTransferService, SiteTransferService>();

// 注册视图模型（瞬态）
services.AddTransient<MainViewModel>();
services.AddTransient<InstanceManagerViewModel>();
services.AddTransient<SettingsViewModel>();

// 注册视图（瞬态）
services.AddTransient<MainWindow>();
services.AddTransient<InstanceManagerWindow>();
services.AddTransient<SettingsWindow>();
services.AddTransient<MergeInstancesWindow>();
// ExtractSiteWindow 需要动态传入源实例 ID，通过 ActivatorUtilities 创建，不直接注册
```

WebView 服务，负责：

- 打开开发者工具
- 导航事件

#### IInstancePackageService / InstancePackageService
实例包服务，负责：
- 将实例（标签页会话 + 备注 + Cookie 登录状态）导出为实例包（`.cbx`，本质是 zip）
- 从实例包导入实例，并恢复登录状态
- 读取实例包清单（`manifest.json`）

#### ISiteDataService / SiteDataService
站点数据服务，提供实例中「站点级」数据的读写原语，是提取网站/合并实例功能的底层支撑：
- Cookie 读写删：通过隐藏窗口的 `CookieManager` 明文搬运（写入时由本机密钥重新加密，会话 Cookie 转为 30 天持久 Cookie）
- `GetStorageOrigins`：从 `IndexedDB` / `WebStorage` 目录名解析来源地址（如 `https_chat.deepseek.com_0.indexeddb.leveldb` → `https://chat.deepseek.com`）
- `CopyStorageForHosts` / `DeleteStorageForHosts`：按网站复制/删除 IndexedDB 与 WebStorage 目录
- Local Storage 批量读写清：因 Local Storage 是整个配置文件共享的单体库（`Local Storage\leveldb`），无法按网站复制目录，
  改为通过隐藏窗口导航到站点后用页面脚本读写。导航结果区分「成功 / 导航失败 / 跨源跳转」三种状态：
  导航失败在读取时汇总为一条“N 个站点无法访问”，跨源跳转则单独记录警告并注明实际跳转地址（写入/清空失败时同样提示）
- `IsHostMatch`：网站归属判断，支持父子域双向匹配（Cookie 域 `.deepseek.com` 与网站 `chat.deepseek.com` 视为同一网站）

#### ISiteTransferService / SiteTransferService
网站迁移服务，负责：
- `GetSitesAsync`：分析实例中的网站列表（来源为 Cookie 域与站点存储来源）
- `ExtractAsync`：把源实例中指定网站的登录状态提取到新实例，可选从源实例移除
- `PreviewMergeAsync`：预览多实例合并结果，列出冲突网站（同时存在于多个来源）
- `MergeAsync`：把多个实例的网站数据合并到目标实例，冲突网站按用户选择保留的数据来源

### 实例导出与导入

#### 背景

实例的数据目录（同时也是 WebView2 的用户数据文件夹）位于
`%LocalAppData%\SimpleBrowser\Instances\{InstanceId}`。其中 Cookie 由 Chromium
使用 AES 加密，密钥保存在 `EBWebView\Local State` 并由 **Windows DPAPI（机器 + 用户绑定）**
保护。因此直接把整个实例目录复制到另一台电脑后，Cookie 无法解密，**登录状态会丢失**。

#### 实现方式

登录状态由两部分构成，需分别处理：

**1. Cookie（通过 API 明文搬运）**

Cookie 由 Chromium 加密，密钥受 DPAPI 保护，不能直接复制。改用
`CoreWebView2CookieManager` 以明文方式搬运：

- **导出**：**先不关闭实例**，复用实例已缓存的 `CoreWebView2Environment`
  创建 [CookieHostWindow](../Core/CookieHostWindow.cs)
  （离屏隐藏窗口），调用 `GetCookiesAsync(null)` 读取**已解密且含内存中未落盘部分**的全部
  Cookie；随后才关闭实例。
  > 关键点：若先关闭实例（会强制结束 WebView2 进程），内存中尚未写入磁盘的 Cookie
  > （尤其是刚登录产生的 Cookie）会直接丢失，导致导出后无法保留登录状态。
- **导入**：用 `CreateCookie` + `AddOrUpdateCookie` 逐条写回，由目标机器自动用本机密钥重新加密。
  由于 WebView2 不会把**会话 Cookie** 持久化到磁盘，导入时统一转换为 30 天有效期的持久 Cookie。

**2. 站点存储（直接复制目录）**

`Local Storage`、`IndexedDB`、`WebStorage`、`Session Storage` 等目录未使用 DPAPI 加密，
可跨机直接复制，用于承载把登录令牌保存在 localStorage / IndexedDB 的站点
（例如 chat.deepseek.com 的登录态）。

- **导出**：实例关闭后，将这些目录压缩进实例包的 `storage/` 下（跳过 LevelDB 的 `LOCK` 锁文件）。
- **导入**：先清空目标实例对应目录，再复制回去（须在创建 WebView2 环境之前完成）。

#### 实例包结构

| 条目 | 说明 |
|------|------|
| `manifest.json` | 清单（实例 ID、备注、导出时间、标签页数、Cookie 数、是否含站点存储） |
| `cookies.json` | 明文 Cookie 列表（名称/值/域/路径/过期/SameSite 等） |
| `session_state.json` | 会话状态（标签页列表） |
| `LastPage.json` | 上次访问页面 |
| `note.txt` | 实例备注 |
| `storage/` | 站点存储目录（Local Storage / IndexedDB / WebStorage / Session Storage） |

> 注意：`cookies.json` 为明文，等同于账号凭据，请妥善保管实例包。
> 目标电脑需安装 WebView2 Runtime 与 .NET 8 运行时。

### 提取网站与合并实例

#### 功能说明

| 功能 | 入口 | 说明 |
|------|------|------|
| 提取网站到新实例 | 实例管理窗口 →「提取网站」按钮 | 把所选实例中指定网站的登录状态（Cookie + 站点存储）独立到新实例 |
| 合并实例 | 实例管理窗口 →「合并实例」按钮 | 把多个实例的网站数据合并到目标实例，冲突网站由用户选择保留哪个 |

两个功能都基于「网站」组织数据：网站 = Cookie 域 + 站点存储来源（含父子域双向匹配）。

#### 提取网站流程（`ExtractAsync`）

1. 读取源实例的 Cookie 与 Local Storage（**在停止实例之前**读取，以获取浏览器进程内存中的最新数据）
2. 停止源实例，释放站点存储目录的文件占用
3. 创建新实例
4. 复制站点存储目录（IndexedDB / WebStorage，**必须在创建新实例的 WebView2 环境之前完成**）
5. 写入 Cookie 与 Local Storage（由 WebView2 自动用本机密钥重新加密）
6. 若勾选「同时从源实例移除所选网站的数据」：删除源实例的存储目录、Cookie，并清空对应站点的 Local Storage

#### 合并实例流程（`MergeAsync`）

1. 读取各来源实例的登录状态快照（Cookie / 站点存储来源 / Local Storage）
2. 停止所有涉及的实例（含目标实例），释放文件占用
3. 按网站确定归属来源：无冲突网站自动取第一个来源，冲突网站取用户在对话框中选定的来源
4. 先清空目标实例中相关网站的站点存储目录，再复制归属来源的目录
5. 删除目标实例中相关网站的旧 Cookie，再写入归属来源的 Cookie（避免新旧登录状态混合）
6. 清空目标实例中将要覆盖来源的 Local Storage，再写入归属来源的数据

> 来源实例的数据在合并后保持不变（仅处理过程中被停止）。

#### 实现要点

- **Local Storage 按来源操作**：`Local Storage\leveldb` 是整个配置文件共享的单体库，无法按网站复制目录，
  只能通过隐藏窗口（[CookieHostWindow](../Core/CookieHostWindow.cs)）导航到站点后用页面脚本读写；
  候选来源除已知的站点存储来源外，还会补充 `https://主机名`，以覆盖仅有 Local Storage 数据的网站
- **时序要求**：文件类操作（复制/删除存储目录）必须在创建或复用 WebView2 环境之前完成，否则目录被浏览器进程占用
- **写入前重建环境**：写入/删除前通过 `RemoveEnvironment` + `GetOrCreateEnvironmentAsync` 重建环境，避免使用已失效的缓存环境

### 实例重命名与描述

入口：实例管理窗口工具栏的「重命名」「修改描述」按钮，以及实例右键菜单。

**重命名（`IInstanceService.RenameInstanceAsync`）**

实例 ID 同时是数据目录名，因此重命名本质是移动实例数据目录：
1. 校验新名称（非空、不含非法文件名字符、不与已有实例重名）
2. 实例正在运行时先停止实例，并清理 WebView2 进程与环境缓存，释放目录占用
3. `Directory.Move` 移动实例数据目录（会话、Cookie、站点存储等随之迁移）
4. 同步迁移以实例 ID 为键的备注记录，清理实例缓存
5. 刷新列表并保持选中重命名后的实例

> 重命名后实例数据不会丢失；但外部若保存了旧实例 ID（如自定义脚本、快捷方式），需要自行更新。

**修改描述（`IInstanceService.UpdateInstanceNote`）**

描述保存在实例备注文件（`instance_notes.json`）中，仅修改备注文本，不触碰实例数据，运行中的实例也可直接修改。

### 实例列表交互（框选与右键菜单）

实现在 [InstanceManagerWindow.xaml.cs](../Views/InstanceManagerWindow.xaml.cs)，列表 `SelectionMode` 为 `Extended`。

**鼠标框选**

- 列表上层叠加一个 `IsHitTestVisible=False` 的 `Canvas` 用于绘制选择矩形，鼠标事件仍由列表接收
- 左键按下记录起点；移动距离超过 4 像素且起点不在滚动条/列表表头内时才开始框选（小于阈值保持普通单击行为）
- 框选期间接管鼠标捕获，按矩形与各列表项边界（`TransformToAncestor` 换算到列表坐标）的交集更新 `IsSelected`
- 按住 Ctrl 框选时在原有选中项基础上追加，否则清空后重新选择
- 框选过程中暂不同步选中集合（避免每次移动都刷新视图模型），松开左键或丢失捕获时统一同步

**右键菜单**

- 菜单项：打开实例 / 停止实例 / 删除实例 / 重命名实例 / 修改描述、导出实例 / 导入实例、提取网站到新实例 / 合并实例
- `ContextMenu` 不在可视化树上，通过 `DataContext="{Binding PlacementTarget.DataContext, RelativeSource={RelativeSource Self}}"` 绑定到视图模型
- 右键点击未选中的实例时，先把该实例切换为选中项，使导出、提取网站等单项操作作用于右键点击的实例
- 打开/停止/删除三个命令通过 `[RelayCommand(CanExecute = ...)]` 按选中状态控制可用性，并在选中集合变化时通知刷新

## 构建和运行

### 前置要求

- .NET 8.0 SDK
- Visual Studio 2022 或 VS Code
- WebView2 Runtime

### 构建项目

```bash
cd <项目根目录>
dotnet build
```

### 运行项目

```bash
dotnet run
```

### 发布项目

#### 普通发布（框架依赖）

```bash
dotnet publish -c Release -r win-x64 --self-contained true
```

#### 便携版发布

项目 `scripts` 目录提供了 `发布便携版.bat`，双击即可输出便携版：

```bat
cd /d "%~dp0.."
if exist "publish" rd /s /q "publish"
dotnet publish CustomizedBrowser.csproj -c Release -r win-x64 --self-contained true -p:PublishTrimmed=false -o "publish"
```

输出目录：`<仓库根目录>\publish`

| 项目 | 说明 |
|------|------|
| 形式 | 整个文件夹（非单文件），约 174 MB / 506 个文件 |
| 运行时 | 自包含（self-contained），内置 .NET 8 运行时，目标机**无需安装 .NET 8** |
| 裁剪 | 关闭裁剪（`PublishTrimmed=false`），WPF 与 WebView2 依赖反射，裁剪会导致运行异常 |
| WebView2 | **未内置**，仍依赖目标机已安装 WebView2 Runtime（Win10/11 随 Edge 自带） |
| 程序数据 | 仍写入 `%LocalAppData%\SimpleBrowser`，**不在便携目录内**，迁移实例请使用「导出/导入实例」 |

> 若要连数据一起带走，可先在各实例上执行「导出实例」，到目标机再「导入实例」。

## 常见问题

### Q: 如何添加新的设置项？

A: 
1. 在 `Models/BrowserSettings.cs` 中添加属性
2. 在 `Views/SettingsWindow.xaml` 中添加 UI 控件
3. 绑定到 `SettingsViewModel.CurrentSettings`

### Q: 如何添加新的实例操作？

A:
1. 在 `Services/IInstanceService.cs` 中添加方法定义
2. 在 `Services/InstanceService.cs` 中实现方法
3. 在 `ViewModels/MainViewModel.cs` 或 `InstanceManagerViewModel.cs` 中添加命令
4. 在视图中添加按钮并绑定命令

### Q: 术语表中没有我需要的术语怎么办？

A: 先在[术语表](./术语表.md)中添加新术语的定义，经过审核后再在代码中使用。
